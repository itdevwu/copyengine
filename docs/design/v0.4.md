# copyengine 0.4 design

Status: draft, updated as the design settles. 0.4 builds two things, in
this order:

1. **Tile IR**: copies whose unit is a group of elements instead of one
   element, so quantization with per-group scales (static or computed from
   the group's amax), dequantization and packing happen while copying.
2. **TMA / cp.async** (sm90+): bulk tile copies, also where copy kernels
   are confined to a few SMs.

It also carries what 0.3 left open: bandwidth limits for copies with device
indices, `segments` / `indices` through the C++ ops and as plan parameters,
less Python per `step(...)` call, transposes sized by element, and whether
copyengine still needs a pinned pool of its own.

## 1. Tile IR

### The model

Today a statement is `dst[D(i)] = f(src[S(i)])` over a domain of elements,
`f` a per-element function (cast, scale, clamp). 0.4 keeps that form and
changes what the domain is made of:

    dst_j[D_j(u)] = f_j(src_1[S_1(u)], ..., src_k[S_k(u)])   for each unit u

- A **unit** is `g` consecutive elements in the row-major order of the
  trailing dimensions of the data (a group of 128 along the hidden size, a
  whole token, a whole KV page). An element copy is the unit `g = 1`.
- Each access maps a unit to its part of a tensor: the data access to `g`
  elements, a scale access to one element (a projection of the domain: the
  unit index, with any strides; broadcast where several units share one).
- `f` sees exactly its unit's inputs and produces its unit's outputs. What
  happens inside (an amax, a division, packing two FP4 values per byte) is
  invisible to the planner, as the rounding of a cast is today.

Three rules decide what may become a unit function (the admission line):

1. **A unit is never split.** Every cut the planner makes (runs, chunks,
   staging rounds, padding trimmed, allocation boundaries) falls on a unit
   boundary; a unit lies in one allocation.
2. **`f` reads only its own unit.** No reduction across units (a tensor-wide
   amax, a softmax, a prefix sum) and no output whose size depends on values.
   A tensor-wide quantity is an input (a scalar source), computed elsewhere.
3. **`f` comes from a closed catalog**, each entry with one host
   implementation shared by host code and kernels (`convert.hpp`) and a
   torch recipe it matches bit for bit (NaN for NaN). No user code.

What does not pass stays outside copyengine. What passes is a new catalog
entry, not a change to the IR.

### Planning

- An op carries its unit size, its extra sources (scales in) and extra
  destinations (scales out), each an endpoint and an access. Its footprint is
  one interval list per side; dependencies and waves are computed over all
  of them.
- Lowering, merging and 2-D recovery work on units as they do on elements
  (a unit is a larger element), so a group of copies quantized the same way
  still merges and batches.
- Element-wise copies are unchanged: `g = 1`, one source, one destination.

### Catalog, first version

Every entry has a torch recipe below; `x` is the input widened to float32
(exact for bf16 / fp16), divisions and products are float32 (no FMA), casts
round to nearest even.

**Scaled formats** (`fp8_e4m3`, `fp8_e5m2`, `int8`; `qmax` 448, 57344, 127):

- Dynamic quantization, per unit (outputs `q` and `scale`):

      amax  = x.abs().amax(-1, keepdim=True)        # over the unit; NaN propagates
      scale = amax.clamp(min=eps) / qmax             # eps = 1e-12 unless given
      q     = (x / scale).clamp(-qmax, qmax).to(fp8)
            # int8: torch.round(x / scale).clamp(-127, 127).to(torch.int8)

- Static quantization: the same `q` with `scale` given (one per unit, or one
  scalar).
- Dequantization: `y = (q.float() * scale).to(out_dtype)`.

**MX formats** (`mxfp8_e4m3`, `mxfp8_e5m2`; OCP MX v1.0): units of 32, an
E8M0 scale per unit, `emax` 8 / 15:

      m, e  = torch.frexp(amax)                       # amax = m * 2**e, m in [0.5, 1)
      shared = (e - 1 - emax).clamp(-127, 127)        # floor(log2(amax)) - emax
      shared = where(amax == 0, -127, shared)
      q      = (x / ldexp(1.0, shared)).clamp(-max, max).to(fp8)
      scale  = (shared + 127).to(uint8)  # as float8_e8m0fnu; NaN amax: 0xFF, q NaN

**NVFP4**: units of 16, an E4M3 scale per unit, and a float32 global scale
`gs` given per tensor (computed elsewhere: rule 2):

      s  = (amax / 6 / gs).clamp(max=448).to(float8_e4m3fn)
      q  = where(s == 0, 0, x / (s.float() * gs)).clamp(-6, 6) -> E2M1 (nearest even)
      packed two per byte, element 2i in the low nibble (float4_e2m1fn_x2)

Each recipe is written once in the tests as torch code; the host and GPU
paths must reproduce it bit for bit, on random data and on the edges (zero
units, NaN, Inf, values at and beyond the format's maximum, subnormals).

### Strategies

- **On the GPU**: a tile kernel, one warp per unit (a block for long units),
  reading and writing device memory, or pinned host memory directly where
  zero-copy is admitted.
- **Compress, then move** (GPU to host): quantize into device staging, then
  DMA the smaller `q` and `scale`.
- **Move, then compress**: DMA the raw data, then quantize on the side that
  receives it (the host executor's threads for host destinations).
- The torch recipe is the baseline where the caller's tensors allow it
  (the same rules as today's native copies); the tuner measures the rest.

### API

```python
ce.quantize(x, q, scale, fmt="fp8_e4m3", group=128)          # dynamic: writes scale
ce.quantize(x, q, scale=s, fmt="fp8_e4m3", group=128, static=True)
ce.quantize(x, q, scale, fmt="nvfp4", global_scale=gs)
ce.dequantize(q, scale, out, fmt="fp8_e4m3", group=128)
```

`x`, `q` and `out` may be `ce.lazy(...)` views (gather pages, then quantize,
in one pass) and work inside scopes and step plans like other copies.

### Order of work

1. IR and planner: units, extra sources and destinations, multi-interval
   footprints; element copies unchanged (all current tests).
2. Scaled formats: host implementation and torch recipes first (bit-exact
   tests on the CPU), then the GPU kernel.
3. MX, then NVFP4 with packing.
4. Compress-then-move and move-then-compress as strategies.

## 2. TMA / cp.async

To be written when the tile IR has settled: a unit of the tile IR is what a
TMA box moves. Admitted per GPU by a verified test copy; sm90 and later only.

## Testing

As in 0.3: every catalog entry against its torch recipe, bit for bit, on
the host and on the GPU; planner tests that no cut splits a unit; the GPU
matrix (`just test-gpu-matrix`) on each GPU generation before a release.
